## CheckRun vs CommandPolicy (no duplicate, no contradiction)
CommandPolicy decides *whether to ask* (SAFE/ASK/RISKY, Normal mode). CheckRun decides *whether it may run at all and in what form* (Linux workspace, every mode) and runs first; the Policy then sees `Result.script`. Overlaps: rm/shred/unlink/find -delete (Policy RISKY; CheckRun blocks only outside the workspace), sudo (Policy RISKY; CheckRun strips it), mkfs/dd/shutdown (Policy RISKY; CheckRun blocks), curl\|sh and push --force (Policy RISKY; CheckRun warns), chmod outside (Policy RISKY; CheckRun blocks on / and host paths). CheckRun is never looser. Roots differ on purpose: CommandPolicy also counts /home; CheckRun is the /root + /tmp Linux rule. The A team checked curl\|sh per simple command after splitting on `|`, so it never fired; CheckRun checks the whole script.

## Wiring (left unwired: P2 adds zero lines to Agent.kt). Exact hooks for the P2 lead (Agent.kt unchanged on `overhaul/p2` up to 794d986c)
1. **run_shell** (`Agent.runTool`, `"run_shell" ->` ~L5191), only when `args.optBoolean("linux")`: before `cmdOk(...)`, `val c = CheckRun.check(cmd)`; if `!c.ok` return `"Not run: " + c.errors.joinToString("; ")`; else run `c.script` (warnings appended to the result); `CheckRun.deletesEdited(c.script, gate.edited)` non-empty → `CheckRun.deleteMsg(...)`; `CheckRun.detachServers(c.script, id)?.script` replaces the script when non-null. After the run: `gate.onRun(c.script, RunResult(code, out, timedOut))`, `stepGuard.after(cmd, res)` (stop = end the loop with its hint), result text from `CheckRun.feedback(res, hint)`.
2. **file_write / file_edit** (DevTools branch ~L5210): `gate.onWrite(path)` after success.
3. **Final reply** (where `ClaimGuard.unbacked` runs, ~L4023): `gate.canFinish(shown)` → re-prompt with `message` when `!ok`; `ClaimGuard.RunClaimTurn.onFinal(shown, ranAnyTool)` (BOUNCE → hide + re-prompt with `RUN_CLAIM_MSG`); `ClaimGuard.unranShellFence(shown).flag` → re-prompt with `FENCE_MSG`; `ReplyShape.interrogates(shown).flag` → one re-prompt with `INTERROG_MSG`; `ReplyShape.isNarration(shown)` with no tool call → `NARRATE_MSG`; `ReplyShape.dropFiller(shown, before = toolsRan)` before showing.
4. **Text-call fallback** (~L3879): append `?: TextCalls.fenceCalls(seen, allTools)` to the existing chain.
5. **User message / reply** (before the model call; after the reply): `HarmCheck.precheck(user)` refuse → answer `reply`, no model call; `HarmCheck.postcheck(user, reply).action == "replace"` → show `reply`, run no tools.
6. **done_job** (`team/JobTools.kt` `doneJob()`, P1-TM-05, before `jobs.done(...)`): call `ToolVerify.doneProblems(...)` with the run's written / attached paths and gate; non-empty → `Out(false, "[done_job] not done: …")`, job stays running (blocked after the retry budget). `doneProblems` is `suspend` (py/sh checks run in the workspace), so `doneJob` needs a suspend path or a pre-computed verdict from the run. Android `DoneProbes`: stat/read via the workspace bridge, `exec` via `Terminal.run(linux = true)`, `jsError` via QuickJS or a WebView (default `JsSyntax`).
StepGuard's step cap is per shell run sequence and stays under SF-06's turn step budget (40 + Go on); keep SF-06 as the turn cap and use StepGuard for the repeat/three-failures stop. Per-turn objects (`CompletenessGate`, `StepGuard`, `RunClaimTurn`) live beside `loopGuard` (~L1662) and reset with it (~L3506). Through TeamHooks/ToolRouter once P0's seam lands.
