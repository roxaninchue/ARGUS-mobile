## Rules
- **Overrides, not copies.** A `BotPolicy` field left null keeps the bot's own `Permissions` value (team.db `bots.permissions` once P0-TM-01 lands); a bot whose fields are all null is dropped from the store.
- **Spending.** Default allowance 0 → every spend asks. `spendVerdict(chain…)`: every bot in the chain is checked against its own allowance with its own month's spending, then `SpendGuard.lowest(chain)` with the actor's spending; first DENY, else first ASK, else ALLOW. ALLOW → `Ctx.spendPreApproved = true` (Policy still asks when proactive / tainted). DENY (over a per-purchase max, bad amount) → `Decision.Refuse` (unless Policy already refused).
- **Sending.** `NONE` → SEND is NEVER for that bot (Policy refuses, along the whole chain); `DRAFT_ONLY` (default) → draft card; `KNOWN_CONTACTS` → one recipient, no CC, someone the user has messaged before, not public → `Ctx.sendPreApproved`; `ANY` → any private message. Public posts never. Chain = lowest scope.
- **Autonomy.** The override replaces `Permissions.autonomy`; Policy already takes the lowest along the chain.
- **Standing rules.** Listed from `PolicyStore.all()`; "Ask again" = `PolicyStore.clear(tool, botId)` (exactly that row). ALLOW rows for classes that can't be pre-approved (SEND, SPEND, DELETE, CREDENTIAL, COMPUTE_PAID) are listed but marked "not used".
